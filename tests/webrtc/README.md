# WebRTC call checks for Tchap desktop

Local fixtures and helpers for checking [tauri-plugin-webrtc](https://github.com/crabnebula-dev/tauri-plugin-webrtc)
calls from Tchap's own UI: 1:1 voice and video with Element Web in Chrome, and
Element Call. Everything runs on one machine, on loopback. Nothing in this
folder is part of the shipped app: the Rust side only reacts to the
`TCHAP_WEBRTC_*` environment variables described below.

On Linux, WebKitGTK has no WebRTC and the plugin supplies it. On macOS,
WKWebView has native WebRTC, so the test build forces the plugin's shim over it
with `TCHAP_WEBRTC_FORCE_SHIM=1`. The same shim, engine and signalling code run
on both; WebKitGTK-specific behaviour (portal picker, GStreamer decoders) is
only covered on Linux.

## Prerequisites

- Node 20 or newer, Rust, the Tauri prerequisites for this repo.
- `coturn` and `livekit-server` (`brew install coturn livekit` on macOS).
- `uv` for the Synapse venv (`brew install uv`). Synapse is a Python fixture.
- Google Chrome for the browser side. Playwright's Chromium has no H.264.
- tauri-plugin-webrtc at a commit whose engine starts when `force_shim` is set
  (`main` from f7e9af5 on). `Cargo.lock` on this branch pins one; to move it,
  run `cargo update -p tauri-plugin-webrtc` in `src-tauri` and commit the lock.

## Setup, once

```sh
cd tests/webrtc
npm install
node setup.mjs                 # Synapse venv, Element Web and Element Call into .fixtures/
cd ../..
npm run fetch-package -- dev   # the tchap-web build into src/
node tests/webrtc/patch-tchap-web.mjs   # point it at the local homeserver (see below)
(cd src-tauri && cargo build)
```

`patch-tchap-web.mjs` edits the fetched build in `src/`, which is git-ignored
and regenerated by `fetch-package`. Run it again after every fetch, then
rebuild: the build embeds `src/`.

## Run

```sh
cd tests/webrtc
node fixtures.mjs        # Synapse, coturn, proxy, Element Web; creates users and a DM
node m4-fixtures.mjs     # M4 only: livekit-server, JWT service, Element Call
./run-tchap.sh           # Tchap with the shim forced; Cmd+Opt+I opens the inspector
open -a "Google Chrome" http://127.0.0.1:8080/
```

| Side | Login |
| --- | --- |
| Tchap | `tchap@example.test` / `pw-tchap` |
| Element Web | `element@example.test` / `pw-element` |

A DM room between the two users exists after the first fixtures run. Use the
call buttons in the room header.

Ports: 8008 proxy in front of Synapse (8018), 3478 coturn, 8080 Element Web,
8081 Element Call, 8009 LiveKit JWT service, 7880 livekit-server.

`node probe.mjs` starts Tchap through the test hook, reports whether the shim is
installed, and logs in through the UI. Use it to check a rebuild without
clicking.

## Procedures

Record for each check: date, Tchap commit, plugin and qrtc commits, OS and
webview version, pass or fail, and the artefacts below.

**M2 voice.** Tchap calls Element Web, talk both ways for 60 s. Element Web
calls Tchap, answer in Tchap. Echo: Tchap on speakers and built-in microphone,
the Chrome side on another device or with headphones, listen for the Chrome
voice coming back. Relay only: in Tchap, Settings, Voice and video, turn off
"Allow Peer-to-Peer for 1:1 calls"; matrix-js-sdk then uses
`iceTransportPolicy: relay` and the selected candidate pair must show a `relay`
local candidate. Evidence: `getStats()` from both sides, a screen recording,
an audio recording of the echo test.

**M3 video.** Video call both ways. Screen share from Tchap, then from Chrome.
Screenshots of Tchap with local preview, remote video and the control bar all
visible, also after resizing and in fullscreen. Evidence: screenshots,
`framesDecoded`, `frameWidth`/`frameHeight`, negotiated codec on both sides.

**M4 Element Call.** With `m4-fixtures.mjs` running: start a group call in a
room from Element Web, join with three Chrome profiles, then join from Tchap.
Check everyone sees and hears everyone, the call shows as encrypted, and the
LiveKit log carries no decodable media. Evidence: screenshots, `getStats()`
from Tchap, which video layer the SFU forwarded.

**Evidence.** Paste `stats-dump.js` into the inspector console (Tchap) or
Chrome devtools (Element Web) during a call. It prints the selected candidate
pair, transport (`tlsGroup`), codecs, inbound and outbound RTP for every
matrix-js-sdk call.

## What the fixtures change in Tchap's web build

Tchap 4.21.5's login screen needs an OIDC (MAS) homeserver, and its dev config
routes DM calls through Element Call. `patch-tchap-web.mjs` makes these
test-only edits to `src/`:

1. `config.json`: one homeserver, `http://127.0.0.1:8008`; `element_call.url`
   set to the local Element Call; PostHog analytics removed;
   `tchap_features.feature_use_ec_in_dm` set to `[]` so DM calls take the
   matrix-js-sdk 1:1 path (set `["*"]` to test Element Call in DMs).
2. `TchapUtils.fetchHomeserverForEmail` honours a `base_url` in the identity
   lookup answer instead of building `https://matrix.<hs>`. The proxy answers
   that lookup.
3. Links and redirects to `#/email-precheck-sso` go to `#/login`, and
   `showScreen("login")` dispatches `start_login`, so the classic password
   login shows.

The proxy also answers MatrixRTC transport discovery (`/.well-known/matrix/client`
and the MSC4143 `rtc/transports` endpoint) with the local LiveKit JWT service.

## Rust side on this branch

- `tauri-plugin-webrtc` as a macOS dependency, registered only when
  `TCHAP_WEBRTC_FORCE_SHIM` is set (`src-tauri/src/lib.rs`).
- `capabilities/macos-webrtc-test.json`: `webrtc:default` for the main window
  and the `http://127.0.0.1:8081` widget origin, so the shim can reach Tauri
  IPC inside the Element Call iframe.

## Known limits

- One machine: the echo test needs the Chrome side elsewhere or on headphones.
- The Element Call widget is cross-origin to Tchap's window. Whether the shim
  installs inside that iframe (through the `remote` capability) is unverified.
  Production Tchap has the same question for its Element Call origin.
- `shim-e2e.mjs` on macOS against Chrome 154 fails H.264 with Chrome as the
  offerer: the shim sent 6 frames. Open in the plugin.
