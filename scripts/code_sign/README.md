
# Sign artifacts for windows 

## Using signtool and signing only the installers
To sign only the installer, you can use the script `sign-single-file.sh`. You will have to download the artifacts that needs to be signed first from https://github.com/tchapgouv/tchap-desktop/releases .

Modify `/src-tauri/tauri.conf.sign-windows.json` if necessary. To find the new certifcate thumbprint use `certutil -scinfo`.


## Using signtool with the tauri bundler
In order to have a complete signature of tchap-desktop, we need to rebuild from sources and run cargo bundle with our desire signature config.
For each env (DEV, PREPROD, PROD). The command needs to be run twice :
- One for the updater release
- One for the no updater release

Exemple of workflow 
```
1. ./direct-windows-build-and-sign.sh x86_64-pc-windows-msvc dev 4.21.4
Once finished move and renamed filed generated to desire places

2. Rename and move the released and signed artifacts into the desire directory by using 
`./move-and-rename-bundle.sh ENV VERSION`

3.Then re-rrun the command to generate no updater artifacts
`./direct-windows-build-and-sign.sh x86_64-pc-windows-msvc dev 4.21.4 true skip skip`
This will rerun the command using the no updater config and without re running the pull of the sources and build of the frontend. We just build tauri and bundle it.

4. Rename and move the released and signed no updater artifacts into the desire directory by using 
`./move-and-rename-bundle.sh ENV VERSION NO_UPDATER`

5. Repeat 1, 2, 3 and 4 for each environement. There should have each 6 artifacts at the end (msi, exe, sig, no_updater.msi and no_updater.exe). Remember that you **cant skip** frontend build between the steps because we need the correct homeserver frontend config for each ENV.

6. Finally, update the latest.json file with the corresponding sig and signed artifacts name. They won't be the same as the one generated by the CI and needs to be updated (new signature and filename with _signed).
./update-updater-file.sh VERSION ENV

```

Once done, upload those artifacts to github release.

## Using osslsigncode and signing only the installers
After creating a release with the standard process. The 
Depending on your platform, choose to use `sign-release-ossl_linux.sh` or `sign-release-ossl_mac.sh`.

This will create the releases with our signed certificate, that can be found in code_sign/releases/VERSION using ossl and a hardware token certificate.

### Release process after signature
Once the build artifact are re-signed, it render obsolète the updater plugin signature. In other word, the signature from the latest_*.json files are not correct anymore. Since, the signature from this file is used to match the update to download, we need to update those signature.

This is the role of the `update-updater-sig.sh` script. It takes the new artifacts and sign them again with minisign and the corresponding private key for the environmenent. The key used to sign should correspond to the public key (correct key pair) fill in tauri.conf.json for the updater.


### Finalize the release
- Upload the newly signed artifact and updated latest.*.json file into the correct github release 
- Create the PR on tchap-infra side in order to push the new signed artifacts on our server
